## 2. 能可靠关联什么，不能关联什么

[54 条失败覆盖表](failed-attempt-coverage.csv)保留任务标签、turn/step、结算序号、错误码、
记录中的 SDK 零值、流活动存在性及显式重试连接，不包含原始请求/响应正文。
[机器汇总](evidence-summary.json)记录范围与限制。

| 类别 | 数量/状态 | 严格含义 |
|---|---|---|
| 正常结算 | 259 | 沿用已证的逻辑结算，不因此宣称费用已服务端复核 |
| 失败且已有独立实际用量证据 | 本轮取得的可确认案例 0 | 只是没有取得证据，**不是实际消耗为零的失败有 54 次** |
| 失败但实际用量无法取得 | 54 | TRANSPORT 48、PI_AI_ERROR 6；全部列为 failed_usage_unavailable |
| 显式重试 | 45 条确定连接 | 失败结算 → 相同任务/turn/step 的下一 llm/retry-started |
| 没有后续显式重试即关闭 | 9 | 不等于没有内部重连、不等于没有费用 |
| 零 usage 前已有流活动 | 5 | 加强零值不可直接当真实成本的警告；不据此估算 Token |
| 隐式回退/重连 | unknown | 不能从“没有持久事件”推导次数为 0 |
| 取消用量 | unknown | 原材料未观察到取消样本；错误回合/会话续接不自动等于用户取消 |

关联只使用已提交事件的任务、turn/step 与序号顺序，没有按相近时间强拼 provider 请求。
一个逻辑尝试可能对应多个底层请求；会话标识或 prompt_cache_key 也不是每次请求的唯一 ID。
仅有时间窗口，在并发请求、时钟偏差和隐式回退存在时不能建立唯一映射。

## 3. 已解决与仍未知的成本项

已解决的是**证据分类和显式逻辑链路**：54 次失败都未被误归为免费，45 条显式重试逐条可追溯，
259 次正常结算保留与失败不同的证据等级。没有重新执行任务或回写原实验结果。

未解决：

- 54 次失败的实际输入、输出、缓存及可得推理 Token；
- 服务端是否接收、执行、结算及是否计入订阅额度/账单；
- 每个逻辑尝试对应的物理请求数、回退/重连次数及其用量；
- 取消和硬中断时的最终用量；
- 货币费用、完整历史 Token 总量及净收益。

规范化零值被原样保留为“SDK 实际记录了什么”；另设 actual_failed_usage/cost=unknown，
不篡改旧记录，也不把默认零升级成 provider 权威零。
正常结算数据不能补齐失败缺口；不能删掉失败后只对成功子集声称完整成本比较。

## 4. 是否确实需要 canary

**不建议为本轮历史对账申请 canary。** 新调用不能恢复旧 54 次失败已经缺失的服务端回执，
也不能证明过去是否发生了隐式回退。普通成功请求尤其不能证明失败用量已解决。

未来若目标改为“验证新测量接线”，canary 可以验证新的关联键、工具配对、错误/取消的
记录行为，以及在已有权威用量源时是否能对账。它仍不能：

- 追溯还原没有关联依据的旧费用；
- 只靠规范化零值确认失败或取消免费；
- 在服务端仍不提供用量时，证明新的失败成本完整；
- 用一次成功代表所有重试、回退或取消路径。

当前优先项不是花钱生成新样本，而是取得下一节的既有窄字段证据。

## 5. 需要用户/平台提供的最小证据与条件式后续方案

### 最小既有证据

先提供一份脱敏字段样例及来源说明即可，不要提供认证材料或完整请求/响应。
范围应由平台限定在原 18 个已授权会话，不能给整账户全部调用后让本审查读取无关记录。

| 字段/保证 | 最小用途 |
|---|---|
| provider、请求模型、可得服务端模型标识及路由配置版本 | 证明仍为同一路由，而非其他模型的用量 |
| provider request/response ID 或可一致比较的去标识化值 | 连接客户端与服务端记录；成功标识可先验证映射方法 |
| 当时的客户端会话/逻辑尝试 trace 关联键 | 失败无 response ID 时仍需桥接；只有共享缓存键不够 |
| 物理请求 ID、父逻辑尝试、retry_of/fallback_of/reconnect_of、传输类型 | 区分显式重试和内部多次发送，避免重算或漏算 |
| 请求开始/结束 UTC、精度/时钟基础、终态 | 辅助核对；时间不能代替唯一关联键 |
| usage 原字段及存在性、计量来源、最终/待结算状态 | 分开 provider 最终计量、SDK 默认值、确证不计费与缺失 |
| 输入/输出/缓存读写、可得总量与推理 Token、字段口径 | 防止把含缓存输入再重复加算；缺失不补零 |
| 可得收费/额度消耗、币种、费率版本或权威免计量说明 | 货币无法提供时仍明确 unknown；权威零须有出处 |

若失败的请求 ID 当时没有保留，平台还需提供可验证的历史桥接关系；不能要求本审查凭时间猜配。
可先用一个既有正常回执及一个既有失败回执确认口径，再对全部 54 次失败及相关物理分支核对。
缺少任何失败分支，就继续保留全成本 unknown。

### 如人工另行决定验证未来路径

本轮没有提出或执行可运行的新 canary 排期。若人工批准另一个目标为未来接线验收，可审议
[既有条件式方案](../runner-measurement-admission-2026-10-21/REPORT.md#6-是否需要最小-canary需要条件式验收不获授权不运行)：

- 同一 provider/model、批准的固定 effort、现有认证与沙箱；不换路由，不用全权限 minimal 配置。
- 短工具任务加一次受控取消，最多三次逻辑尝试；取消动作本身也须明确授权。
- 自动重试和内部传输回退必须能够记录或限制。当前尚未验证，不能承诺物理请求不超过三次。
- 成功、重试、取消都可能消耗订阅额度或产生费用。金额及取消费用 unknown。
- 当前未证明 Token 参数是后端硬上限，也无可核验货币上限；不得承诺“最多某金额”。
- 必须先有可对账的窄字段用量源；否则新增 canary 仍解决不了实际用量证据问题。
- 若需要新采集能力或更大权限，先停止并另行审查；本轮不开发 Runner、不扩权限、不绕认证。

授权范围至少应涵盖准确模型配置、逻辑尝试/重试/回退、取消动作、墙钟停止条件、认证使用、
非敏感采集字段和可能费用/额度风险。未经用户明确批准，一律不发送新请求。
