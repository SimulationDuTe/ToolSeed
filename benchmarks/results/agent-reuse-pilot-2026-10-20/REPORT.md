# ToolSeed 真实 Agent 跨任务复用试验报告

**结论：本轮没有观察到自主保存或 Procedure 复用，也没有证明扣除全部成本后的净收益。**
主试验的 A、B 各 9 个任务全部通过独立验收，但 B 的 9 个 Agent 都没有尝试保存能力。
B 共执行 5 次检索，结果全部为空；保存、指引交付、采用均为 0。不能把空库检索解释为检索质量失败，
也不能把任务完成率相同解释成 ToolSeed 在一般任务上无效。

基线：`c0cac122c1a149e3f6c1a2501a683db323fc5131`，`develop`，开始时工作树干净。
本轮不改 Core、Schema、四工具协议或现有实验框架，不提交、不推送、不发布。

## 1. 已有实验资产与完成状态

审查依据为 [P0 最小价值实验及完成定义](../../../docs/P0-SLIM.md#112-最小价值实验) 和
[产品成功定义](../../../docs/DESIGN.md#33-最终成功定义)。机制跑通不等于真实净收益。

| 资产 | 实际性质 | 可以支持什么 |
|---|---|---|
| [确定性参考实验](../../value_experiment.py) | 脚本按预设步骤数计操作，完成状态为 simulated | 保存、检索、交付、结果记录与计数机制；不支持真实 Agent 效率 |
| [live 框架](../../live_experiment.py) 的 ScriptedAgent | 直接返回任务 expected 的 oracle | 框架机制测试，不是价值证据 |
| 同一框架的 CommandAgent | 外部 Agent 接入点 | 可运行真实 Agent，但本机未发现可用的外部 Agent CLI |
| [既有运行说明](../../README.md#pilot-log-not-evidence) 中的两任务人工试跑 | 文档记录 A/B 各 2/2，成功率差 0；时间与 Token 缺失 | 有限交付/采用线索，不能证明净收益；未找到可独立复核的完整原始结果 |
| 本轮试验 | 同一 Harness 的真实子会话修改文件、运行程序，父会话独立验收 | 当前受控任务上的实际行为和完成结果；不足以证明普遍收益 |

现有 live runner 会为每个 B 实例预置库，运行后删除该库，并把 `deliveries > 0` 标为 adoption。
这不能直接回答“Agent 自行识别机会、创建能力、跨任务使用”的问题。因此没有重复跑 oracle，
也没有把该字段当作本轮采用证据。复用了其 TaskInstance 验收和 AgentResult 数据形状，
用临时实验驱动补充持久 B 库、真实新会话及可核验文件结果；现有框架源码未修改。

## 2. 任务集、A/B 条件及可重复性

主试验冻结为 3 个领域，每领域一个初始任务和两个后续变体，共 **9 对、18 个真实任务上下文**。
所有初始任务完成后才开始第一变体，第一变体完成后才开始第二变体。
后续任务不获得前一个 Agent 的对话；只有 B 的 ToolSeed 数据库跨任务保留，且初始为空、没有手工种子。

- **A**：正常文件/终端/Python 工具，无 ToolSeed 使用指导，不访问其他任务或外部方法库。
- **B**：相同基础工具、解释器、权限和配对输入，另提供当前 packaged Skill 和实际 LocalAdapter
  的四接口，通过仅允许四个工具名的日志化 CLI 桥接。允许不搜索、不保存、不复用。
- 解释器统一为工作区 Python 3.13。任务不使用网络，不允许安装依赖；任务输入及不可改文件有 SHA-256。
- 使用相同默认子 Agent 设置，未指定模型/provider override；**确切子会话型号、采样参数不可见**。
  父会话期间发生过模型切换，严格模型一致性没有得到验证。
- 任务隔离依赖单独目录、全新上下文和指令约束，**不是 OS 安全隔离**，没有完整跨目录读取审计。
- A 也不共享前任务脚本；因此它不是“已有普通共享脚本库或原生 Harness 记忆”的基线。
- 这是实际执行文件/进程的人工构造小任务，不是真实生产事故集；任务较容易，存在完成率天花板。
- 这是 LocalAdapter 四接口实验，未测原生 MCP 注册常驻上下文及持久 stdio 会话的完整成本。

冻结方案见 [预注册](preregistration.md)，任务描述、期望值和输入哈希见 [任务规格](task-spec.json)。
原始 fixture builder、指令、Agent ID、桥接收据、解答与验收日志保留在
[原始工件目录](../../../.test-data-agent-value-main/)；复现需使用新目录、新空库和新任务上下文，
不得覆盖旧试验。原始 TaskInstance 验收是程序判定，不依赖 Agent 自称成功。
精确复现模型行为及费用仍需要可固定、可计量的 AgentRunner。

## 4. 机会识别、保存、检索、采用的分阶段结果

| 阶段 | 观察结果 | 证据强度/解释 |
|---|---|---|
| 机会识别 | B 的 9/9 简短报告称存在复用机会 | Agent 自报，不是独立质量评分；A 未被同样提问，不能比较识别率 |
| 抽象与保存 | save 尝试 0、候选 0、能力 0、版本 0 | 桥接收据和真实 SQLite 均确认；没有 capability_id/version_id 可列，非遗失数据 |
| 检索 | 5 次，都返回空列表 | 实际调用正常；库为空，不能归因为关键词排序或适用性失败 |
| 内容读取 | toolbox_run 0、Invocation 0 | 不把 search 结果或提供手册算作 Procedure 内容交付 |
| 实际采用 | 已交付 0、关联自报采用 0 | 没有被保存 Procedure 的跨任务采用证据；不以“交付即采用”填数 |
| 后续任务结果 | A/B 后续各 6/6 通过 | 靠各自临时解法，不构成 ToolSeed 复用收益 |
| 不适用边界 | 未得到实际可复用候选 | 无法验证不适用能力拒绝；方法边界变体不等于硬 OS/工具冲突测试 |

B 的共同理由是问题短小、标准，适合直接 L0 处理；部分任务先检索，再因空结果直接完成。
即使报告“有复用可能”，也没有支付外化成本。这个结果可以与当前 Skill 的成本门控一致，
不能强制解释为 Agent 失误，也不能事后补种能力来制造采用。

主库 Schema 为 6，最终只有 **5 个 search_performed 事件**，没有保存、交付或 task_outcome_signal。
18 个任务成功保存在实验验收记录中，**没有为填统计向 ToolSeed 注入模拟成功**。
四工具预检使用了单独数据库，其中的测试 Procedure 不属于主试验，不能充当主试验的保存/采用。

## 6. 失败案例与限制

1. **接入安装缺口**：初始桥接从任务目录启动时 `ModuleNotFoundError: toolseed`。
   仓库 cwd 可导入不等于虚拟环境已正确安装。标准 editable 安装当前项目后，独立预检四接口通过。
   第一次受限构建还遇临时目录写入拒绝，授权沙箱外原样安装成功；没有修文件权限或改 Core。
2. **会话中断**：第一变体 6 个任务及 data2 A/B 共 8 个任务中断，均续接原上下文、保留输入与
   started 标记，不以新样本替换。精确原因 unknown；父模型切换不能单独证明原因。
   详情见 [中断记录](interruptions.md)。
3. **验证故障**：部分 Agent 的 tempfile 子目录写入/清理被拒；有 PowerShell 引号及临时断言
   SyntaxError。错误保留在逐任务报告中，不将问题复现本身误算成无效重试，也不把失败次数填为 0。
4. **处理条件有限**：没有原生 MCP 上下文成本测量，模型参数未固定、没有随机化与盲法，
   目录隔离不是强制隔离，没有完整工具遥测。
5. **样本太容易且无保存**：完成率天花板；未触发能力抽象/持久化，因而没有检验“已有合适能力时
   是否采用”或“多次复用能否摊销创建成本”。

## 7. 当前能与不能支持的结论

**能支持的事实**：这 18 个真实 Agent 文件任务的冻结验收全部通过；可用的四工具是可选项，
Agent 确实可以选择不保存；当前样本中自报机会与实际外化之间存在明显断点；主库没有形成能力。

**合理解释而非证明**：任务太短，Agent 可能合理地认为外化不划算；这与其报告和 Skill 的 L0
选择相符，但没有完整成本数据来证明其经济判断正确。

**不能支持**：跨任务 Procedure 采用、正净收益、提速、独立验证带来的因果收益、多个领域的
复用泛化、自主学习或通用能力增长。三个领域均完成任务，不等于三个领域均发生了能力复用。
也不能由此证明 ToolSeed 一般无效或语义检索/自动维护等新机制已经必要。

本轮完成了有限的真实 A/B 行为试验，**没有关闭 P0 复用价值与净收益假设**。
此前机制和质量门禁通过不改变这个结论。本轮未重跑产品质量门禁，未将其充当价值证据。

## 8. 下一项最小改进建议

**下一步先改实验，不改 Core。** 预注册一个更有实际重复成本的任务族，明确提供已发生/即将发生
的复用次数证据，仍允许 Agent 放弃保存；使用可固定模型并导出 Token/完整工具账本的 AgentRunner。
A 保留日常项目文件等正常复用方式，B 只额外增加可选 ToolSeed，检验其增量价值。
只有自发创建能力且至少一个新任务实际采用后，再讨论摊销与净收益；否则继续报告未触发，
不强迫保存、不临时补种、不为了拿到正结果加样本。

当前证据不支持新增场景规则、语义检索、自动反思或维护子系统。
