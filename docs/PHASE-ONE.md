# 第一阶段：适用条件、反例与证据质量

日期：2026-10-25。当前工作树增量，未发布。

本阶段落实项目评审中六项基础修正：

1. 平台/宿主按可选项匹配，required_tools 按全部需要匹配。部分、空、缺失或错误格式的上下文
   明确保留未知；完整空工具清单须显式声明。没有新增 Manifest 字段。
2. ID 直查用于查看，会显示适用冲突；交付使用相同判断，已知冲突时拒绝且不生成 Invocation。
3. 搜索与交付补齐内容哈希、结构化适用条件、条件检查和最新验证的有界摘要。
4. 明确无条件禁止语句可以保存；有条件例外或引用反例的歧义内容进入 candidate，不能自动交付
   或仅凭验证记录晋升。继续逐项检查全文、拒绝真实凭据及明确的越权/泄密指令。
5. ready 版本可追加带哈希的验证；事件和有效性声明在同一事务写入。记录验证不改内容、状态
   或 current，candidate 晋升的独立来源/通过结果/有效性/回归门槛仍适用。
6. 同 invocation/source/outcome 重试返回原事件，历史重复记录在统计时去重且原文不变。
   维护按不同 task（否则 invocation）计算失败，排除 stale/superseded、关联错误和哈希冲突，
   保留来源、归因未知；执行诊断决策时再次核查证据。

边界：静态扫描不证明内容安全；环境匹配不授予权限、不替代自然语言前提判断。验证来源为调用方
声明，验证摘要只覆盖所记录案例。任务结果信号数不等于独立任务数。矛盾结果保留为不同信号，
纠正可追加 superseded 评估。未知验证或结果不填为成功。

兼容：四个公共 MCP 工具、candidate protocol_version=1、七字段 Manifest 和 SQLite schema v6
保持不变；无需重写或迁移现有库。新增响应字段，已知条件冲突的交付有意改为拒绝。
源码 Skill 已同步，用户已安装 Skill/插件未自动更新。

回归覆盖见 `tests/test_phase_one.py`：依赖缺项、部分清单、ID 冲突、反例/真实指令混合、验证
失败与失效、并发反馈、历史重复、待处理诊断证据变化，以及损坏验证记录。已有晋升和维护测试
